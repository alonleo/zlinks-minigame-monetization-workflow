# 资源构建与分包协议

## 1. 包归属

推荐按实际项目映射以下职责：

- 启动壳：本地最小 Loading、离线重试 UI、基础服务和必要配置。
- 高频共享内容：小型稳定公共包，禁止把“共享”变成全项目合集。
- 主界面：独立功能包，只包含当前展示和必要交互。
- 战斗：按地图、怪物组、角色、技能及其访问关系划分。
- 设置、结算、商店、活动：独立或紧密关联的功能包，按需取得。
- 音频：随场景或功能组织，不默认首屏下载完整音频库。

`AlibabaPuHuiTi-3-105-Heavy.otf` 是所有小游戏统一默认字体，由 SDK Core 有意安装为本地资源，不按普通资源回流判错；但仍必须在真实播放器报告中记录其精确字节数、引用闭包和压缩后影响。

粒度需平衡请求数量、入口下载量、共享关系、更新频率和内存。公共资源归属必须稳定，不能取决于构建顺序。关卡必要资源集是逻辑准备集合，不等于主包。

## 2. 依赖分析与动态地址

构建工具生成地址 → 包、包 → 版本/校验、包 → 依赖的映射，并展开 Unity 序列化依赖。检查 `Resources`、本地场景直接引用、预加载资产、全局 Shader/变体、字体、图集、渲染配置、插件默认资源和自动注册入口，防止远程业务资源回流主包。

运行时字符串和 JSON 配置引用必须由构建规则显式解析。分组可声明序列化 `roots` 与配置 `references`；选择器必须产生非空、唯一、类型匹配的地址。无匹配、文件缺失、归一化地址冲突或依赖环必须构建失败。场景与普通资源原则上分组；实际依赖环需要明确修正或合并加载单元，不能递归跳过。

远程场景从播放器本地场景集合排除，但保留原 GUID、来源类型、场景路径和代码保留信息。Bundle 中的脚本和引擎模块仍须随播放器编译。

## 3. Catalog、版本和轻量启动索引

Catalog 与 Bundle 使用同一不可变内容版本。先发布内容寻址文件，再发布可引用它们的入口元数据；禁止单独覆盖共享 Catalog 使旧客户端混入新内容。

完整 Catalog 本身可能是大量业务数据。首包体积受其影响时，可在本地只保留包含内容版本、平台、构建目标、播放器版本、CDN 根和版本化 Catalog 文件名的轻量描述；首次业务请求再获取完整 Catalog。并发请求共享一次目录准备，失败可重试，并拒绝错版本、错平台、错播放器或递归描述。编辑器预览可保留完整本地目录，但播放器替换必须在失败路径恢复源文件。

轻量索引增加一次网络请求，因此必须分别测量首屏出现和入口可操作，不能把工作移到首屏后就声称总启动变快。

## 4. 可选本地共享字体

仅当启动壳已经必须包含某字体时，远程 UI 才可声明复用该本地来源。构建工具应备份并记录原始哈希，临时转换已识别引用，验证 Bundle 不再嵌入字体，恢复源字节/meta/GUID，再核对字体仍在本地打包报告。中断状态不明时拒绝新构建，不覆盖未知用户修改。不得为使用此能力把完整游戏字体重新加入首包。

## 5. 真实产物审计

分别统计平台主包、平台 Data/资源子包、唯一主 WASM 和远程内容。区分平台下载集合、引擎启动必需集合和首个玩法入口集合；资源位于 CDN 但启动仍阻塞等待时，启动成本并未消失。

读取 `player-packed-assets.json` 或等价报告，按真实字节排序并追踪大资源直接/间接引用。重建后比较相同口径报告、压缩产物和符号/代码保留结果。不能因界面未直接使用某系统就推断其代码或插件资源已退出包，也不能整体盲删仍被业务需要的渲染管线或模块。

报告中的序列化字节、压缩主包、网络下载量和内存占用是不同口径。历史项目体积、Bundle 数量和单次优化结果只能作为调查线索，不作为当前候选结论。

## 6. 远程发布集合

远程目录只包含当前候选声明的播放器 Data、完整 Catalog 和 Bundle 等资源；平台代码包及唯一主 WASM 仍交给平台开发者工具。上传源目录内容直接映射到版本前缀，不额外套目录。清单记录相对路径、字节数和 SHA-256，并与游戏运行时配置一致。实际上传与公开 CDN 校验由专项上传 skill 执行。
