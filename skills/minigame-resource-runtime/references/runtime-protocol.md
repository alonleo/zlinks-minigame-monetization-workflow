# 资源运行时协议

## 1. 分层与统一契约

- 游戏业务：打开 UI、进入场景、选择技能；不拼 CDN、不下载物理包。
- UI、场景、音频、实例池服务：管理生命周期，等待资源准备后继续原操作。
- 资源服务：解析地址和依赖，统一本地、文件缓存和远程结果，管理共享请求、错误和句柄。
- 调度与平台适配：提供有限并发、优先级、超时、有限重试和文件缓存。

统一异步能力至少等价于 `AcquireAsync`、`SpawnAsync`、`OpenAsync`、`EnterAsync`、`PreloadAsync` 和只查内存的 `TryGetLoaded`。本地命中可立即完成，但禁止主线程同步等待网络，也禁止启动下载后返回空值冒充完成。

请求键至少包含地址、类型和内容版本。并发请求共享底层任务，每个调用者保留自己的取消、完成结果和资源持有关系；取消一个等待者不得中断其他使用者。同一 Bundle 可共享下载，前台正式请求优先于后台预载。

错误必须区分可恢复网络失败、清单缺项、404、类型错误、版本不兼容和代码/组件裁剪。临时文件完成校验后才能成为有效缓存；坏缓存可清除后有限重试，不能无限下载或把所有失败都描述为网络问题。

## 2. UI、场景和业务提交

UI 打开顺序为：取得预制体 → 在未激活状态创建 → 一次性结构初始化 → `PrepareAsync` 准备本次必要内容 → 设置参数 → 激活显示 → 完成请求。必要内容未就绪前不显示半初始化界面；装饰资源允许占位，但迟到结果必须核对绑定对象仍有效且未被复用。

重复点击应合并或排队并保留原参数。返回、切场景或关闭等待后，迟到请求不能弹出旧页面。异常和取消路径必须在 `finally` 中释放遮罩、输入锁、暂停令牌和句柄。依赖远程资源的工作从 `Awake/OnEnable` 移到显式准备阶段。

场景准备与激活分离：准备阶段取得来源和依赖，不提前占用不可撤销的 Unity 激活操作；业务允许后才提交激活。激活提交前可取消，提交后等待完成。场景来源句柄保留到真实 `sceneUnloaded`。

资源准备与业务提交分离。发奖、扣体力、消费广告资格、保存结算或切换活动配置只能在准备成功且原业务上下文仍有效后执行一次；重试资源不能重复业务副作用。

## 3. 战斗、对象池与预加载

进入关卡或波次前准备立即必要的地图、角色、怪物和初始技能。局内新增技能、武器、投射物和特效在启用前准备；关键资源失败不得静默跳过或提前消费。对象池空且资源未就绪时走统一异步入口。

预加载只优化性能，关闭后正式请求仍须正确。预载不得创建业务实例、执行初始化、发奖或保存。预取与正式请求共享任务；正式请求可提升排队中依赖的优先级。预载失败只记录具体错误，不能污染后续正式重试。

切换视图、进入后台、禁用宿主或销毁时释放预取所有权，但不得取消其他调用者仍持有的共享请求。低内存后释放预取引用并避免立即自动补满；下载并发、后台槽位和每帧解包/实例化预算必须通过目标平台实测调优，不能把某一历史项目数值设为通用常量。

## 4. 句柄、内存、版本与代码保留

UI、场景、战斗会话和对象池分别持有来源句柄，最后一个使用者释放后才允许回收依赖。文件缓存与内存驻留分开管理；卸载内存不删除下载文件。禁止无条件 `Unload(true)` 破坏仍在使用的对象。

低内存入口应合并并发回收请求，通知各缓存宿主清理闲置内容，至少跨一帧等待延迟销毁，再调用 `Resources.UnloadUnusedAssets`。单个宿主失败不能阻止其他宿主清理；回收不应进入普通启动或按钮等待，也不强制删除平台文件缓存或执行托管 GC。

Catalog、Bundle 与播放器使用一致的不可变版本并记录构建目标和兼容信息。远程 Bundle 使用的脚本、反射类型和引擎模块必须保留在播放器中；重下载资源不能恢复已被裁剪的代码。

## 5. 最小项目接入与验证

每个游戏至少提供稳定地址规则、UI/场景注册、动态配置依赖解析、启动路由和必要资源集合。同步旧调用需要一次性接入改造，不能假设框架会自动暂停并恢复任意旧函数。

验证至少覆盖：冷缓存且关闭预载、慢网和断网恢复、404/类型/版本错误、连续点击、加载中退出、切场景、失败重试、回收再加载、长时间运行，以及图集、Spine、音频、技能、怪物、引导和对象池等非普通弹窗资源。编辑器可模拟延迟/失败；微信和抖音仍需验证真实远程资源、缓存、内存和代码裁剪行为。
