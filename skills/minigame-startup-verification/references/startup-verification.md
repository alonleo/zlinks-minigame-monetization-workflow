# 启动与迁移验收协议

## 1. 启动路线与终点

首次玩家建议路线：本地静态加载界面 → 第一关必要资源 → 第一关可操作 → 后台预载。再次进入建议路线：本地静态加载界面 → 主界面必要资源 → 主界面可操作 → 按操作加载。

启动壳应尽快呈现最小静态加载画面，再启动后续准备；同帧重活不能抢占首屏。但静态画面出现不等于进入游戏完成，也不证明引擎/WASM、资源准备或首关已达标。

分别记录平台封面、Unity 首场景、目录可用、入口资源就绪和首次可操作。需要时再拆分引擎/WASM、配置/身份、关键下载、解包和场景激活。

## 2. 测量口径

每组结果记录设备、系统、网络、平台包版本、资源版本、缓存状态和计时终点。区分冷启动、文件缓存命中和内存命中，固定条件取得多次样本。删除最近玩记录、重新扫码或 `needDownloadDataPackage=false` 不能单独证明冷缓存；必须使用明确的缓存清理方式并核对实际下载日志。

存在重叠的阶段区间不能直接相加。平台面板的阶段统计不能未经事件时间线核对就解释为纯编译或纯下载耗时。包体大小不能直接换算成固定秒数；模型估算必须标记 `estimated-only`。

看到 SDK 日志不等于 SDK 阻塞启动。区分异步入口、入口中的同步工作、回调重活和网络竞争；不得为提速破坏登录、广告或平台生命周期。

正式候选强制关闭 WASM 函数分包。验证配置、产物和加载器只引用唯一主 WASM；日志出现 `wait for func`、`fetch js`、`wait wasm func` 或等价函数子包行为即失败。Brotli、符号裁剪、资源外置和函数分包影响不同维度，不能互相替代证据。

## 3. 正确性矩阵

至少覆盖冷缓存且关闭后台预载、慢网、断网恢复、有限重试、404、清单错误、类型/版本错误、连续点击、加载中退出、切场景、回收再加载和长时间运行。验证入口可操作，不只验证加载画面出现。

首包/远程内容调整后检查新手引导的迟到目标与布局变化、免费资格的单次消费、对象池粒子/拖尾/位置/动画复用状态，以及远程 Bundle 对应代码和引擎模块是否被裁剪。出现未识别组件时先核对代码保留，重下载资源不是修复方案。

验证顺序优先补齐时间线和首包依赖证据，再处理仍在包内的大资源、插件默认资源和渲染依赖，随后评估代码裁剪与体积编译。每项优化使用同一口径前后对照，不把多个同时变化的结果归因于其中一个动作。
