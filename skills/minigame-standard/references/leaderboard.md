# 小游戏排行榜规范与模板

本文件仅在小游戏任务确认需要排行榜时读取。先沿项目实际入口、平台 SDK、存档和结算链路定位数据来源，再复制或适配 `assets/leaderboard/`；模板不是对现有成熟实现的替换授权。

## 1. 默认产品合同

- 首页排行榜入口默认打开一个独立弹窗，弹窗内以“好友榜 / 全国榜 / 省份榜”三个页签切换窗口。三个窗口共享弹窗外壳、页签区、指标说明、列标题、滚动榜单、固定条目、分享入口和关闭入口；只替换各窗口的数据源、列语义与状态内容。只有项目平台或后端明确不支持某一窗口时才删去对应页签，不得用模拟数据或空壳页签补齐数量。
- 默认移除单独的标题栏和“排行榜”标题文本，使用三个纯矩形页签承担窗口标题。页签复用当前游戏的标题框配色和描边，选中态通过更亮底色、指示条或轻微缩放突出；页签整体可有约 `2/3` 高度突出弹窗顶部。页签下方直接衔接指标说明与榜单区域，不保留无用途的空白带。
- 默认列为“名次 / 头像 / 玩家 / 成绩”。成绩名称与玩法一致，例如通关数、最高分、最短用时或最少步数；排序方向必须与指标语义一致。好友榜和全国榜保持相同列网格，省份榜可将头像/玩家列替换为省份简称徽章/省份名称，但名次与成绩列仍与其他窗口对齐。
- 列标题固定。排行条目位于可滚动区域，本人数据按真实成绩和名次参与其中；同时在滚动区域外固定显示本人条目，使其滚动后仍可见。仅本人有数据时，中间排行区域也必须显示本人，不能因另有固定本人条目而留白。
- 本人已上榜时显示真实名次和成绩；本人无数据或未进入榜单时仍保留本人条目，名次显示“未上榜”，成绩使用项目约定的空值符号。
- 前三名默认使用金、银、铜奖牌；其他名次使用数字。奖牌是装饰资源，不拦截点击。
- 头像先绘制本地占位图，再由平台头像覆盖。头像 URL 为空、下载失败或解码失败时保留占位图；昵称为空时显示平台或项目约定的默认昵称。

### 三个窗口的数据合同

- **好友榜**：微信小游戏从开放数据域读取好友关系数据，主域只负责弹窗外壳、页签切换和共享画布承载。展示结构默认与全国榜一致；前三名使用金、银、铜徽章，头像位于徽章与玩家文本之间，玩家文本左对齐，固定本人行始终存在。
- **全国榜**：从项目真实后端或平台全量榜接口读取，不把编辑器样例、机器人或预置测试记录冒充真实玩家数据。默认保留分享入口、列表外固定本人行和增量分页；分页大小服从接口，滚动接近底部时根据服务端 `hasMore` 请求下一页，追加时去重，并隔离切换页签后的迟到响应。
- **省份榜**：展示省级行政区真实汇总数据，列表外固定显示本人所属省份条目。后端支持玩家省份查询与更新时，提供“我的省份 / 选择省份”入口并使用稳定行政区编码；选择后真实上报、刷新并匹配本人省份名次。后端没有该合同则只展示可验证的数据，不虚构选择能力或排名。
- 三个窗口分别维护加载、空数据、无权限、失败、分页与请求版本状态；切换页签时不得让上一窗口的承载层、滚动位置或迟到响应污染当前窗口。

## 2. 状态必须完整

至少处理以下状态，不用一张静态假榜单代替：

| 状态 | 默认行为 |
| --- | --- |
| 加载中 | 榜单区域内显示轻量加载反馈；不阻塞关闭 |
| 有好友数据 | 按指标排序并渲染；列表可滚动；本人固定在底部 |
| 无好友数据 | 显示“暂无好友排行数据”和简短下一步提示；本人固定条目显示“未上榜” |
| 本人未上榜 | 无论好友列表是否为空，固定本人条目继续存在并显示“未上榜” |
| 无权限 | 显示平台授权或设置指引，不伪装成空数据 |
| 请求失败 | 显示可理解的失败提示；按平台能力允许重试 |
| 头像失败 | 显示本地占位头像，不留透明空洞或破图标记 |
| 长昵称 | 单行省略或按项目规则截断，不挤压成绩列 |

空数据、无权限与请求失败是不同状态，应由真实结果区分。

## 3. 数据与排序

- 排行指标来自真实结算、存档或平台云数据。只有成绩被业务确认后才上报，不用编辑器模拟值或随机值写入正式数据。
- 使用稳定、长期不变的平台 key；变更 key 前考虑历史排行迁移。上报值、显示值和排序值必须表达同一指标。
- 明确高分优先或低值优先。相同成绩按平台时间、首次达到时间或项目既有规则稳定排序，不让同一批数据反复跳位。
- 固定本人条目只是中间排行数据的同步副本，不改变真实排名。中间排行不得过滤本人，所有条目继续显示按完整数据集计算的原始名次；固定本人条目的名次和成绩必须与中间对应条目一致。
- 编辑器可使用明确标识的模拟数据预览外壳；正式平台构建必须隐藏模拟数据，改用真实开放数据域或平台接口。

## 4. 布局与美术

- 优先复用当前游戏的弹窗外壳、标题条、主按钮、字体和描边，不把参考图近似重画成另一套视觉系统。
- 列宽、头像和成绩区域按目标分辨率共同计算；检查安全区、窄屏、长昵称、两位及以上名次和大数值。
- 排行区域应明确裁剪滚动内容，固定本人条目不得被遮罩裁掉或随列表滚动。
- 固定本人条目与普通行使用同一列对齐，可用独立底色突出；前三名奖牌保持相同轮廓与尺寸，仅改变材质颜色。
- 表头、普通行与固定条目必须使用同一列网格。头像中心默认位于名次徽章中心与玩家文本列起点之间；玩家文本左对齐，长昵称单行省略；头像、徽章、字号与行高可以随中间区域同比例放大，但不得越过裁剪边界。
- 页签上移或外壳调整后，指标说明和榜单容器应同步回收空白并连续衔接；滚动区域只滚动数据行，表头、固定条目、分享按钮和关闭入口不得随列表移动。
- 模板奖牌和默认头像位于 `assets/leaderboard/wechat-open-data/images/`。若项目已有更合适的同风格资源，优先替换资源并保持路径或同步更新模板引用。

## 5. 默认字体

- 新建或重做小游戏排行榜时，全部页签、指标说明、表头、普通行、固定条目、空状态、错误提示、分享与关闭文案默认统一使用阿里巴巴普惠体 `Regular`。现有项目已有成熟字体系统或用户指定其他字体时沿用项目选择，不强行换字库。
- “使用 Regular”必须同时满足真实资源与引用闭环：Unity `Text`、TextMeshPro、开放数据域 Canvas 文本、生成器和默认/fallback 配置都指向可用的 Regular；不能只修改字体名称或默认设置，却让组件继续显式引用 Bold、Heavy 或其他静态小字库。
- 默认字形范围覆盖简体中文、英文大小写、数字、常用标点、全部省级行政区名称以及动态中文/英文昵称所需字符。默认不为日文假名、韩文或 Emoji 扩包；项目确实允许这些输入时再加入对应字体或 fallback。动态昵称无法靠静态文案扫描穷举，应从完整 Regular 中保留其支持的中英文范围，或采用具备同等覆盖的动态字库策略。
- TextMeshPro 字体资产默认使用可从源 Regular 补字的动态多图集或等效方案，并绑定真实源字体；静态图集必须证明覆盖上述字符。微信开放数据域不能直接复用 TMP SDF 时，使用平台可加载的同款 Regular WebFont/本地字体能力，并在不可用时提供可读的系统 fallback。
- 删除 Bold、Heavy 或旧字体前，检查场景、Prefab、材质、fallback、图集和构建产物引用。验证至少包含省份名称、中文昵称、英文昵称、数字与常用标点样例；不能把编辑器中显示正常等同于微信构建已加载字体。

## 6. 微信小游戏实现

- 微信好友数据只能在开放数据域读取。主域负责弹窗外壳、打开/关闭与共享画布承载；开放数据域负责好友数据、头像、排序和列表绘制。
- 开启好友关系能力，使用 `sharedCanvas`/开放数据上下文；主域在视口变化时同步开放数据域尺寸，关闭时隐藏开放数据域。
- 默认复制 `assets/leaderboard/wechat-open-data/`：
  - `friendRank.js`：滚动好友列表、固定本人条目、前三名奖牌、头像占位和空状态。
  - `friendRankStyle.js`：列宽、滚动高度、本人固定行和状态样式。
  - `images/`：金银铜奖牌与本地头像占位图。
- 将模板文件安装到微信导出结果的 `minigame/open-data/render/tpls/`、`render/styles/` 和 `render/image/`；安装过程必须校验源文件、目标目录和 SDK 预期片段，SDK 结构变化时明确失败，不能静默漏装。
- SDK 示例中的随机成绩必须移除，成绩由主游戏在真实结算后发送。空数据分支应交给自定义模板渲染，确保“暂无好友排行数据”和固定“未上榜”本人行同时出现。
- `assets/leaderboard/unity/` 是 Unity/团结引擎接入参考。适配项目的编译宏、平台管理器、分享接口、资源路径和现有弹窗资产，不把其中示例路径当作跨项目固定路径。

## 7. 通用生成模板

`assets/leaderboard/leaderboard-template.json` 是生成或实现前的配置起点。按项目修改标题、指标、排序方向、平台 key、分享能力和文案，但保留状态合同；不要把模板示例成绩写入正式运行时。

默认组件层级：

```text
LeaderboardOverlay
├─ Shade
├─ Panel
│  ├─ RankTabs                 好友榜 / 全国榜 / 省份榜
│  ├─ MetricLabel
│  ├─ FriendWindow
│  ├─ GlobalWindow
│  ├─ ProvinceWindow
│  ├─ RankViewport             当前窗口共用列网格
│  │  ├─ ColumnHeader          固定
│  │  ├─ ScrollList           仅数据行滚动
│  │  └─ PinnedRow             固定本人或本人省份，始终存在
│  └─ ShareButton
└─ CloseAction
```

开放数据域可将 `ColumnHeader + ScrollList + SelfRow` 一起绘制到共享画布，但语义和滚动边界仍按此结构实现。

## 8. 验收清单

- 入口能打开与关闭，重复打开不生成重叠实例；遮罩、标题和按钮不越出安全区。
- 0、1、超过可视行数三种数据量均正确；滚动只影响中间排行条目，表头和底部固定本人条目不随滚动移动。
- 本人位于前三或普通名次时，中间排行条目与底部固定条目的名次、成绩一致；仅本人有数据时中间区域仍显示本人。本人未上榜或无任何数据时只显示底部固定的“未上榜”状态，不生成虚假的中间排行条目。
- 金银铜奖牌对应真实第 1/2/3 名；其余名次数字正确。
- 真实头像成功覆盖占位图；空 URL 和加载失败保留占位图。
- 空数据、无权限、请求失败文案互不混用；长昵称和大成绩不破坏列对齐。
- 微信开发者工具检查开放数据域日志、资源路径和共享画布尺寸；至少再用有真实好友数据的测试账号或真机验证。编辑器模拟、静态检查或脚本编译不能表述为平台视觉验收。
- 三个页签的选中态、切换、数据隔离、滚动位置和迟到响应正确；全国榜分页可以超过首屏/第一页，省份榜的本人省份行与选择结果一致。缺少真实接口的窗口不得显示模拟排名。
- 所有排行榜文字实际使用 Regular，并在微信构建中验证省份名、中文/英文昵称、数字和常用标点无缺字；Bold、Heavy 或旧小字库没有残留的显式引用。
