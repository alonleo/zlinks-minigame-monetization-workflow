# Unity 小游戏 QA 面板接入规范

所有 Unity / 团结小游戏目标平台均执行本规范。QA 面板是需求实现阶段内的测试能力，必须进入各平台正式发布包并可打开；它不增加新的大阶段，也不能替代正式玩法、平台 IDE、真机、录屏或网络统计证据。

## 构建与代码边界

- Editor 面板与运行时面板复用同一个项目专用命令服务；命令服务调用项目真实存档、刷新、重载和结算入口，UI 层不复制业务逻辑。
- 运行时 QA 入口、密码框、面板和项目允许的命令服务必须包含在所有目标平台的正式发布构建中，包括微信、抖音及项目支持的其他小游戏、Android、iOS 或桌面 Player；不得再用 `DEVELOPMENT_BUILD` 或测试符号把整套 QA 功能从 Release 编译移除。Editor 专用窗口仍放在 Editor-only 程序集中。
- 水印处理、分包与发布候选门禁、正式录屏及统计核实使用最终 Release 候选；该同一候选必须能够从指定五连击入口完成密码验证并打开 QA 面板。可以另建开发测试包，但不能用测试包存在入口来替代正式候选的逐平台验收。
- 密码属于入口防误触，不应被描述为客户端安全边界。不要把生产密钥、管理口令或平台账号密码复用为 QA 密码，也不要在日志、截图、录屏或阶段回执中输出明文。联网、竞技、付费经济或共享账号数据项目中的高权限命令必须使用服务端授权、短期签名令牌或项目既有等价机制复核；纯离线单机若只使用客户端密码，必须在项目回执中明确记录可被逆向和滥用的风险及已获产品决策。
- 正式候选预检使用正向存在性检查：确认 QA 入口代码、密码弹窗、面板、命令授权策略和项目字体资产均进入最终构建闭包，同时确认默认游戏流程不会意外打开 QA、不会留下常驻遮罩或改变正式玩家入口。

## 五连击与密码入口

- 每个项目必须明确记录一个激活位置，包括场景或常驻 UI、目标节点的稳定路径/标识和有效点击区域。默认推荐使用**设置面板中的“设置”文本节点**：通过序列化引用、稳定 Transform 路径或项目 UI 注册表定位该节点，不按当前显示文案搜索，避免本地化、改文案或字体替换后失效。点击区域跟随文本节点的 `RectTransform`；文本本身不接收射线时，可在同层增加仅覆盖该矩形的测试构建接收器，但不得改变设置页原按钮行为、扩大到整个面板或布置透明全屏接收层。项目确实没有该节点时，再选择版本号、Logo 等不承担破坏性操作的现有可见元素并记录原因。不得依赖屏幕绝对像素。
- 只有命中指定区域的有效点击才累计。连续点击 5 次后打开密码输入框；点击区域外、超过项目记录的连续点击时间窗、场景失效或输入被取消时清零计数。触摸和鼠标/IDE 模拟点击使用同一状态机，同一次物理输入不得重复计数。
- 密码弹窗必须包含遮罩后的密码输入框、明确的“确定”和“取消”按钮，以及可访问的错误提示区域。弹窗适配安全区并拦截后方游戏输入。
- 点击“取消”时关闭弹窗，清空已输入密码、错误提示和连击状态，不改变游戏存档或 QA 解锁状态。
- 点击“确定”时进行项目配置的密码校验。空密码和错误密码不得进入 QA 面板，必须在当前弹窗内显示清晰错误提示；不得把输入值或期望值写入日志。再次输入时可清除旧错误提示。
- 密码正确后清空输入内容和错误提示，关闭密码弹窗并打开 QA 面板。项目应明确 QA 面板关闭后是否需要重新验证；未另行规定时，每次从五连击入口进入都重新验证，不把解锁状态写入 `PlayerPrefs`、游戏存档或云存档。
- 密码来源使用项目已有安全配置方式或按平台/环境注入的项目专用值，不在通用模板、工作流仓库或跨项目共享代码中硬编码统一密码。正式包中的客户端比较值可能被逆向；涉及高权限命令时按上文生产授权策略执行，不能只依赖本地字符串比较。

## 项目字体与字符集

- 密码弹窗、错误提示、按钮、标签、数值、状态栏和 QA 面板全部使用当前项目实际 UI 使用的字体资产及 fallback 链。UGUI `Text` 使用项目 `Font`，TextMeshPro 使用项目 `TMP_FontAsset`；不得默认创建系统字体、下载外部字体或另带一套通用 QA 字体。
- 优先从项目已有 UI 主题、字体配置服务或稳定的现有文本节点取得字体；若代码运行时创建面板，应通过项目专用字体提供器显式注入，不能依赖 Unity 默认字体或按字体名称猜测资源路径。
- 实现前盘点 QA 界面的完整字符集，至少包含标题、字段名、“确定”“取消”、密码错误提示、数字、正负号、常用标点和密码遮罩字符。逐字确认主字体或既有 fallback 覆盖；项目不包含 `•` 时使用项目已覆盖的遮罩字符，不得以缺字方框交付。
- 字体资产、材质、图集和 fallback 必须进入小游戏实际构建闭包。静态引用正常不等于构建中可用；微信和抖音分别在目标 IDE 截图检查全部 QA 文本，在目标真机可用时再检查缩放、裁剪、乱码和缺字。
- 不为 QA 测试工具擅自替换项目正式 UI 字体或扩大正式字体图集。确需补字时沿用项目既有字体生成流程，只添加 QA 所需字符，并记录资源变化和包体影响。

## 运行时面板

- 运行时面板自动创建并跨场景保留，关闭时不留下遮挡正式 UI 的输入层。展开态使用不透明高对比度背景覆盖物理屏幕，内容适配安全区并支持真机手指滚动。
- QA 面板至少按本次测试范围提供确定性状态准备、真实持久化终值检查、安全重载、正常结算链和带二次确认的完整清档；不能用测试旁路替代正式输入链证据。
- 提供只对当次进程生效的“录屏隐藏”，同时隐藏 QA 面板、激活提示和输入遮罩；重启后入口恢复。五连击指定位置保持原 UI 外观，正式包不额外显示 QA 标识，但指定节点的五连击识别仍须可用。

## 验证回执

QA 回执至少记录且不得包含明文密码：

- 激活场景、节点标识、点击区域、密码配置来源和高权限命令授权策略；
- 1 至 4 次点击不打开、有效五连击打开密码框、超时或区域外点击清零；
- 取消关闭且清空、空密码提示、错误密码提示、正确密码进入面板；
- 弹窗和面板不点击穿透，关闭或隐藏后游戏输入恢复；
- 全部 QA 文本实际使用的项目字体资产、fallback 和字符覆盖结果；
- 微信、抖音及所有目标平台分别在最终 Release 候选的 IDE/Player 或真机中验证入口、字体、授权和命令结果；
- 最终候选正向证明 QA 代码与项目字体已进入构建闭包，并证明未触发时无额外标识、无常驻输入遮罩、无正式流程行为变化。
