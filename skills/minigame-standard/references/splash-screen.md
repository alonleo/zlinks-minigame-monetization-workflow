# 小游戏开屏规范

仅在当前任务属于小游戏，且用户要求处理开屏、确认把开屏纳入范围，或开屏是完成构建与发布任务所必需时读取并应用本规范。非小游戏任务不得引用本规范，也不提示处理开屏。

## 定位实际生效入口

- 先沿实际构建链确认平台配置、Build Profile、导出钩子、SDK 模板或生成器、运行时加载页及其 Prefab。不要只凭文件名判断开屏入口，也不要只覆盖一张同名图片。
- 区分平台首次启动底图与游戏内后续加载页。两者需要统一视觉时，同步其资源路径、Sprite 引用和生成逻辑；业务上独立时保留各自配置。
- 同一启动流程同时包含“平台 SDK 引擎初始化页”和“Unity/游戏内普通资源加载遮罩”时，先按实际渲染者区分两个阶段。用户要求仅带真实进度条的 SDK 引擎页显示首次加载提示与健康游戏忠告时，SDK 配置和 Build Profile 应指向原带文案图；仅显示“加载中…”的普通加载 Prefab、场景副本及其生成器应统一指向独立的无文案图，不得继续共用 SDK 背景。系统胶囊、广告位可能覆盖在 Unity 画面上，不能仅凭截图中出现平台控件就判定背景一定由 SDK 渲染。
- 对上述分图方案做引用闭环：同时核对 SDK 配置与 Build Profile、普通加载 Prefab、实际入口场景、运行时 Resources/Addressables 加载路径以及缺失资源时的重建生成器。条件允许时在导出前用 `AssetDatabase` 验证两张图可按预期类型导入、普通加载节点实际绑定无文案图、SDK 导出路径仍为带文案图；避免只改现有 Prefab，下一次重建或切换 Build Profile 后又恢复共用图。
- 生成目录中的文件只用于验证最终产物。默认修改源配置、模板或生成器，避免下次构建把手工修改覆盖。
- 项目已有成熟开屏时，以现有画面、入口、动态进度和构建策略为基线，只修正用户要求的内容。

## 底图、裁切与健康游戏忠告

- 先确认实际显示模式是 `cover`、`contain`、拉伸还是按安全区裁切，并按支持范围内最窄、最高的目标屏幕计算可见安全宽度。竖图在 `cover` 下可能左右裁切，不能只检查原图全尺寸。
- 健康游戏忠告默认使用以下准确文本；用户或平台有明确版本时以其版本为准：

  ```text
  抵制不良游戏  拒绝盗版游戏  注意自我保护  谨防受骗上当
  适度游戏益脑  沉迷游戏伤身  合理安排时间  享受健康生活
  ```

- 忠告放在底部可读区域，使用较小但清晰的字号并居中，完整落在窄屏安全宽度内；不得与加载条、百分比、首次加载提示、系统胶囊按钮、圆角或底部安全区重叠。
- 平台首次启动模板无法可靠渲染字体时，可以把固定忠告烙入底图；能由 UI 组件稳定呈现时优先保留为文本组件。动态进度、百分比和倒计时不得烙入底图。
- 使用生成式图片工具修复底图时，只让模型清理或延展背景，不让模型生成要求逐字准确的中文。最终中文使用项目字体确定性排版，并复核错字、漏字、换行和标点。

## 资源替换与压缩

- 保持构建配置要求的尺寸、格式、色彩模式和透明度。替换现有资源时保留有效 `.meta`、GUID、fileID 和导入类型，除非引用关系本身需要修复。
- PNG 优先做无损优化并比较替换前后体积；不得因重新保存导致包体明显膨胀。需要同步 JPG 备用图时，保持画面与文案一致，但实际配置仍只指向确认生效的格式。
- 写入后重新读取文件，验证格式、尺寸、解码、体积与哈希；编辑器或其他进程可能回写资源时，等待刷新后再检查一次，不能仅以写入命令成功作为已替换证据。

## 引用闭环与验收

- 搜索新旧文件名、资源路径、GUID 和 fileID，至少核对平台配置、Build Profile、导出脚本、Prefab/场景及运行时加载代码。删除或替换资源后不得留下指向不存在 GUID 的序列化引用。
- 配置文件、构建配置和运行时 Prefab 应引用同一份预期资源；若构建脚本只在资源不存在时创建 Prefab，还要检查已经存在的 Prefab，不得假设脚本会自动修正旧引用。
- 验证图片可解码、导入类型正确、无冲突标记，并按目标窄屏比例做一次裁切预览，确认所有固定文本完整可见。
- 只有实际执行并通过平台导出或真机测试时，才能表述为构建或真机验证通过；静态引用与资源检查需明确其验证层级。
