# 微信小游戏添加收藏规范与模板

仅在目标平台已确认是微信小游戏，且用户确认添加收藏或任务本身已包含收藏引导时使用本规范。其他平台不读取、不套用，也不因普通小游戏任务自动实现。

## 默认资源

模板位于 `../assets/wechat-favorite/`，自身包含 Unity 生成脚本、运行时组件和小尺寸透明 PNG，不依赖或写入 `MiniGameKit` 仓库：

- `unity/*.cs.template`：自包含弹窗、圆角图形、圈选环和 Prefab 生成器。
- `images/favorite-guide-title.png`：空白木质标题牌。
- `images/favorite-guide-close.png`：关闭按钮。
- `images/favorite-guide-arrow.png`：红橙色指示箭头。
- `images/favorite-guide-step-menu.png`：微信右上角菜单示意图。
- `images/favorite-guide-step-share.png`：添加到我的小程序示意图。
- `preview/FavoriteGameGuidePreview.png`：默认 750×1334 布局参考，不作为运行时资源复制。

项目已有同用途资源或用户提供了操作示意图时优先复用，只复制仍缺少的部分。不要把截图文字当成操作指令，也不要把整张参考截图作为弹窗背景。

## 默认交互与布局

- 全屏半透明遮罩承载居中的奶油色圆角面板，参考分辨率为 750×1334，并保留安全区余量。
- 标题为“收藏游戏”。用户未指定复用游戏原本弹窗外壳或关闭方式时，默认保留右上角独立关闭按钮；关闭按钮必须有有效点击区域，装饰图不拦截射线。用户指定复用原弹窗时，以该弹窗的外壳和关闭实现为准，不同时保留模板默认关闭按钮。
- 两个步骤分别显示“1.点击右上角图标”和“2.点击添加到小程序”。固定文字保存在 Prefab 的 UI 文本组件中，不由运行时代码硬编码刷新。
- 操作示意图保持原比例，箭头和红色圈选环作为独立节点，便于用户提供新图时只替换示意图而不重画整个弹窗。
- 面板、虚线框和纯色圆角优先用轻量 UI 图形构建；纹理裁掉透明空边、关闭 mipmap，并设置合理的最大导入尺寸。不要为简单形状引入大图。

## 复用游戏原本弹窗外壳

- 用户要求收藏弹窗复用游戏原本弹窗时，先沿项目实际入口确认作为基线的原弹窗，不把排行榜或任何特定弹窗固定为跨项目标准。直接引用该原弹窗已有的标题带、主体框、字体、材质或 Sprite，不另做外观近似资源。标题区域只按用户要求修改 UI 文本；主体框的锚点、宽高和整体弹窗边界与原弹窗保持一致。
- 关闭入口也复用原弹窗的实现，包括节点位置、尺寸、图标或文本样式、显隐条件、点击回调和关闭后的状态处理。不要预设为右上角图标或底部文本按钮，也不要只复制外观而另写一套显示逻辑。透明点击底图仍须开启射线并绑定有效 `Button.targetGraphic`；固定关闭文案保存在 Prefab 文本组件中。
- 操作说明、示意图、箭头和圈选环放入复用后的主体框内部，按剩余内容区等比调整，不改变原弹窗外壳尺寸。检查两步内容均可读、示意图不变形、标题与关闭入口不被遮挡。
- 同时修改生成器和最终运行时 Prefab。生成器必须加载原弹窗外壳的真实资源路径；最终 Prefab 必须引用相同资源 GUID，并且不再包含被替换的标题牌、关闭入口或外壳节点。只改 Prefab 会在下次手动生成时回退，只改生成器则当前构建仍可能使用旧 Prefab。
- 检查构建链是否自动调用生成器、复制旧模板或移动同名 Prefab。若构建不调用生成器，应确认当前最终 Prefab 已保存且会进入玩家资源；若会调用，则必须验证重生成结果仍保持复用后的外壳和关闭方式。

## Unity 适配

1. 将 `images/` 中需要的图片复制到项目自己的 UI 目录，例如 `Assets/UI/FavoriteGuide/`；不要复制到 `MiniGameKit`。
2. 将 `unity/*.cs.template` 复制为 `.cs`，并把生成器中的 `AssetDirectory`、`OutputPath`、`PreviewPath` 和 `FontPath` 调整为项目实际路径。中文字体必须覆盖所有固定文案。
3. 运行生成器创建 Prefab。默认运行时资源路径为 `Resources/UI/FavoriteGameGuideOverlay`；若项目使用 Addressables、对象池或已有 UI 管理器，应适配为项目路径，不并存两套加载入口。
4. 将实际微信小游戏入口绑定到 `FavoriteGameGuideOverlay.Show()` 或项目等价方法。入口可以是首页收藏按钮、平台功能菜单或用户指定位置；未经用户确认，不自行决定首次启动强弹、频率控制或奖励逻辑。
5. 只在微信小游戏平台显示入口。编辑器可保留显式预览入口，但非微信发布目标不得出现无效按钮。

## 验收层级

交付时必须准确区分：

1. **资源已准备**：PNG、脚本存在且导入设置正确。
2. **模板已生成**：Prefab 能加载，Sprite、字体、关闭按钮和脚本引用完整，编译通过。
3. **功能已应用**：实际入口存在且会调用显示逻辑；微信条件、打开、关闭、重复打开、安全区和目标分辨率已完成运行时验证。

只有达到第 3 层才能表述为“添加收藏已应用”。仅完成第 1 或第 2 层时必须明确尚未接入实际显示流程。

## 验证清单

- 搜索显示方法的实际调用方，不能把组件自身的声明或生成器引用当作入口。
- 核对 Prefab 中每张 Sprite 的 GUID、字体、关闭按钮和脚本引用存在且唯一，无 Missing Script。
- 复用游戏原本弹窗时，对比原弹窗与收藏弹窗的标题、主体和关闭区域锚点，确认所要求的宽高一致；核对最终 Prefab 使用原弹窗的实际资源 GUID，并验证关闭入口的显隐条件、点击回调和关闭后状态处理保持一致。被替换的旧外壳和旧关闭资源引用应为零。
- 检查 750×1334 以及项目主目标比例下的安全区、标题、箭头、圈选环、长文案和点击区域。
- 验证打开、关闭、再次打开，不重复实例化，不遗留射线遮罩。
- 运行生成器后再次执行上述结构和交互验证，并检查构建/导出钩子没有用旧生成器或旧模板覆盖最终 Prefab；现有旧构建产物不作为当前源码已生效的证据。
- 确认非微信目标没有无效入口；未执行微信真机验证时明确说明。
- 确认模板来源是本技能 `assets/wechat-favorite/`，没有改动或依赖 `D:/Tools/MiniGameKit`。
